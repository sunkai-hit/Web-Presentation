# Wish-to-Reality Web PPT Production Rules v3

本规则只适用于 `projects/wish-to-reality-reading/`，不影响仓库其他项目。

## 1. 三道硬门槛

### Gate A：内容稿
每一页必须达到已确认的前 1–6 页 demo 的完整度。主体页必须实际写出：完整问题、必要背景、故事/实验/例子、机制解释、作者观点或现代解释、页底结论。禁止用“本页介绍……”代替正文。

### Gate B：页面实现
每一页必须达到“电影院陈爆米花实验”demo 的实现复杂度。不是栏目齐就算完成，而是每个信息块必须真正被视觉化和解释完整。

### Gate C：视觉 QA
只有 A、B 两关逐页全部 PASS，才允许做最终视觉检查。

## 2. 禁止统一卡片模板生成整套

禁止以一个通用 grid / card 模板批量生成全部页面。可以共享颜色、字体、按钮、基础卡片样式，但每个主体页的 DOM / 信息结构必须根据内容单独设计。

## 3. 页面设计稿是必需中间产物

内容稿之后、HTML 之前，必须为每页明确：

- 这一页回答的核心问题；
- 主视觉或核心视觉对象；
- 第一阅读区、第二阅读区、结论区；
- 故事 / 实验 / 机制 / 对照怎样被视觉化；
- Required Blocks；
- 哪些内容不能被压缩掉。

没有页面设计稿，不得直接生成 HTML。

## 4. 爆米花 demo 是最低复杂度基准

主体知识页至少同时具备：

1. 一个核心视觉对象；
2. 一个完整解释过程；
3. 一个具体故事 / 案例 / 实验；
4. 一个机制、流程或对照关系；
5. 一个结论或生活迁移。

缺两项及以上，直接 FAIL。

## 5. 不固定页数

不为了维持固定页数压缩内容。需要拆页就拆页，需要合并就合并。页数服从内容和可读性。

## 6. 先做 6 页样板组

整套制作前先完成以下代表页：

1. Manifestation 概念页；
2. Shinn 十章地图；
3. Shinn 完整机制；
4. 一个 Shinn 故事页；
5. 爆米花实验页；
6. 四书总模型页。

只有这 6 页全部达到 demo 标准，并且视觉语言明显不同，才允许继续整套。

## 7. 内容覆盖检查

每页必须列 Required Blocks。HTML 缺失任一必要块直接 FAIL。禁止把完整内容稿再次压缩成“标题 + 一两句话”。

## 8. 视觉红线

- 16:9 单屏；
- 正文保持投屏可读，不靠缩小字号塞内容；
- 面积超过页面 15% 的容器，不允许只有标题 + 1–2 行文字；
- 主体知识页信息区应真实占用页面主体空间；
- 不能出现大量无意义等高空卡片；
- 阅读顺序必须一眼可辨；
- 必须检查溢出、边界、对齐、字号、空容器、密度一致性。

## 9. QA 记录

每个候选版本都要记录：
1. 内容稿逐页确认；
2. 页面实现逐页确认；
3. 视觉 QA。

前两项未全部 PASS，不得宣称“最终视觉检查通过”。
