# Wish-to-Reality Web PPT Content & Visual Rules

本规则只适用于 `projects/wish-to-reality-reading/` 项目，不作为仓库其他 Web Presentation 项目的公共规则。

## 1. 内容密度基准

本项目以“电影院陈爆米花实验”单页测试稿为基准页。除封面、转场和结尾页外，每一页必须达到以下标准：

1. 每页必须有一个完整问题，而不是单个主题词。
   - 不写“习惯形成”。
   - 写“一个行为怎样从‘我要做’变成‘自然就做’？”
2. 主体页至少包含 3–5 个真实信息区，每个信息区能支撑讲解 20–40 秒。
3. 概念页必须有例子；故事 / 实验页必须有“背景 → 发生了什么 → 结果 → 为什么重要 → 作者如何解释 → 今天如何理解”。
4. 流程图节点必须是小知识单元，包含：名称、定义、机制解释、生活例子。
5. 每页底部必须有“这一页到底说明什么”的结论或转场。
6. 不能再出现大面积空容器：面积超过页面 15% 的容器如果只有标题和一两句话，必须重做。

## 2. 视觉与版式规则

1. 页面不能全部依赖四格卡片；根据内容混合使用作者页、故事页、实验页、流程图、对照表、案例页、总架构图。
2. 每页至少有一种视觉承载元素：书脊/书封卡、人物/作者位、图标、实验示意、流程箭头、矩阵、时间线、场景图或结论条。
3. 页面阅读顺序必须清楚：从标题区进入主体区，再到结论区。
4. 知识页视觉面积使用率目标为 70%–85%，避免上方拥挤、下方空白。
5. 字号不得为了塞内容而过小：正文不低于 13px，关键卡片正文建议 14–16px。
6. 结尾、封面和章节转场页可以适当留白，但必须承担叙事功能。

## 3. 生产流程规则

1. 先提交完整逐页内容稿，再制作 Web PPT。
2. 内容稿不是大纲，必须接近“去掉样式后的 PPT 成品文字”。
3. 每次提交中间产物后，必须回读 GitHub 文件确认写入成功。
4. 最终 HTML 完成后必须做自检：
   - DOM/布局检测：无 slide 内容超出边界。
   - 基础文本检测：无空 slide、无异常短主体页。
   - 视觉抽检：至少截取封面、章节图、流程图、实验页、最终总图进行检查。
5. QA 结果写入项目内 `.project/qa-v0.6.0.md`，不影响其他项目。
